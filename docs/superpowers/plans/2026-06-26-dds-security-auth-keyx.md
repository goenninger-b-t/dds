# WP-DDS-SECURITY-AUTH-KEYX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the secure participant end-to-end, our-to-our: a security-enabled participant authenticates every discovered security-enabled peer over the PSM wire on discovery, exchanges conformant §9.5.2 key material (KxKey-encrypted), strictly gates endpoint matching on authentication, and encrypts/decrypts real user data with the exchanged per-writer keys — dropping the Slice-1 pre-shared test key.

**Architecture:** The auth/key **manager lives in `dds-dcps`** (`auth-manager.lisp`), mirroring `type-gate.lisp`: it holds per-participant state at the `domain-participant` level (`dp-auth-state`) and installs three hooks onto the disc-node (on-participant-discovered, on-stateless-message, auth-gate). `dds-disc` stays crypto-free — it only gains the hook slots + the auth-gate composition at the match site. `dds-security` gains a `keyexchange.lisp` (KxKey derivation + §9.5.2 KeyMaterial + CryptoToken codec) with no disc dependency.

**Tech Stack:** Common Lisp (SBCL + Clasp); `dds-security` over `dds-dare`/OpenSSL FFI; `dds.pal` foreign buffers for secrets; the 2a handshake (`handshake.lisp`/`suites.lisp`/`identity.lisp`) over the 2b-i PSM wire (`stateless-message.lisp` + `dds.security` envelope codec).

## Global Constraints

- OMG DDS-Security 1.1 conformance is non-negotiable; the only allowed deviation is interop behavior added on top, never replacing. False-REJECT is the worst class.
- Never hardcode a wire constant from memory — every §9.5 constant (KeyMaterial layout, KxKey KDF labels, CryptoToken `message_class_id` values) is pinned in T0 from the spec clause + Fast-DDS corroboration (clean-room, no RTI source); cite the clause.
- KATs are published vectors only, fetched from the authoritative source — never self-generated or recalled.
- `defun*` on every function, `defstruct*` on every struct, full `ftype` on every function.
- No hand-rolled crypto (FR-SEC-2): primitives via `dds-dare`/OpenSSL only.
- Secrets (SharedSecret, KxKey, master keys/salts) in `dds.pal:alloc-static/free-static` foreign buffers; never `static-vectors` directly (clasp#1793).
- No reader conditionals outside `dds-pal/`.
- Both impls validate, Clasp first, identically (`make test-clasp` then `make test-sbcl`).
- Every network-facing parser bounds-checked before each read/alloc, fail-closed, even at `(safety 0)`; resource caps on lengths/counts.
- Default (no-identity) path byte-identical + `mem 0.0000` (no per-sample heap alloc).
- Docs in lockstep (docstrings + `docs/wiki/security.md` + `README.md` + `docs/verification.csv`) at the capstone; SBOM auto-regenerated by the pre-commit hook (never hand-edited).
- No AI-assistant attribution in any repo file except the agent-config file; cite "the operating contract".

## Strategy / dependency order

Spike-first. T1 and T4 are independent of the crypto chain (warm-ups). T2→T3 build keyexchange. T5 composes T1–T4. T6 rewires the data path. T7 proves end-to-end. T8 is the capstone.

```
T0 spike ─┬─ T1 algo-vs-suite + select-auth-suite wiring (handshake.lisp)
          ├─ T2 KxKey derivation + KAT ──── T3 KeyMaterial gen + CryptoToken codec + fuzz
          └─ T4 disc extension points (hooks + auth-gate compose + cleanup)
T1,T3,T4 ── T5 auth-manager (dds-dcps) ── T6 rewire crypto to exchanged per-writer keys
                                            └─ T7 integration (headline) + fuzz ── T8 capstone
```
