# ADR 0105 Slice 1 — `take-into` / `read-into` to a genuinely-zero arm

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Add the non-loan `take-into` / `read-into` access operations and drive the new `gate-mem` arm to a
genuinely measured **0 bytes/sample**.

**Architecture:** The application allocates two vectors once (samples + `sample-info`s) and reuses them
forever; `take-into` fills them **in place** under the reader cache lock, copying out of the middleware's
already-decoded pooled struct, then recycles that struct immediately — which the loan variant structurally
cannot do. Reaching a real zero also requires removing five further per-sample allocations on the RX path.

**Tech Stack:** Common Lisp (SBCL + Clasp), `defun*` / `defstruct*` from `dds.lang`, manual vtables (no
CLOS on the hot path), `make gate-mem` as the only allocation oracle.

**Authority:** `docs/adr/0105-a-take-is-not-a-loan-take-into-and-the-type-support-copy-into-slot.md`.
Reasoning + hazard analysis: `docs/superpowers/specs/2026-08-06-take-vs-loan-design.md`.
⛔ **ADR 0105 must be ACCEPTED before Task 1 starts.**

(`(setf (gethash h …) t)`), so the second phase may simply mark every entry and the dedup can be dropped —
but the scratch vector must then be bounded, or a large selection grows it without limit.
