# WP-DDS-SECURITY-ACCESS-CONTROL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver DDS-Security 1.1 AccessControl end-to-end, our-to-our: CMS-verify the signed Governance + Permissions documents (Permissions CA), parse them, and enforce allow/deny at participant creation, local DataWriter/DataReader creation, and remote endpoint matching (a permissions-gate composed as the third sequential gate after the Slice-2 auth-gate).

**Architecture:** Document validation + the data model live in `dds-security` (`access-control/`, no disc dep). The manager lives in `dds-dcps` (`access-control.lisp`), parallel to `auth-manager.lisp`: `%install-access-control` holds `dp-access-state` and installs a `permissions-gate` (third gate after the auth-gate) + the `check_create_*` hooks. `dds-disc` gains one `permissions-gate` slot (like `auth-gate`), crypto/policy-free. The new `cms-verify` lives in `dds-dare`.

**Tech Stack:** Common Lisp (SBCL + Clasp); `dds-dare` over OpenSSL (X.509 + the new CMS verify); a new XML parser dependency (spike-pinned for both impls); the Slice-2 auth manager + identity (`identity-handle-cert`, the `auth-remote` record) for the cert subject names.

## Global Constraints

- OMG DDS-Security 1.1 §9.4 conformance is non-negotiable; the only allowed deviation is interop behavior added on top, never replacing. False-REJECT is the worst class.
- Never hardcode a format constant from memory — the Governance/Permissions XSD element set + the S/MIME-CMS format + the XML lib are pinned in T0 from the spec clause + the OpenSSL/XSD reference; cite the clause.
- No hand-rolled crypto (FR-SEC-2): CMS verification + signature checks via `dds-dare`/OpenSSL only.
- The new XML dependency: justify it in `docs/provenance.md` + the SBOM; it MUST load on BOTH Clasp and SBCL; control-plane only (never on the hot path).
- `defun*` on every function, `defstruct*` on every struct, full `ftype` on every function.
- No reader conditionals outside `dds-pal/`.
- Both impls validate, Clasp first, identically (`make test-clasp` then `make test-sbcl` — NOT bare `sbcl --eval`).
- Every parser bounds-checked + fail-closed even at `(safety 0)`; resource caps.
- Default (no-permissions) path byte-identical + `mem 0.0000`.
- Secrets/handles via `dds.pal` foreign buffers + the handle-based OpenSSL FFI (`%ossl-sym` + `cffi:foreign-funcall-pointer` over `*libcrypto*`).
- Docs in lockstep at the capstone; SBOM auto-regenerated by the pre-commit hook (never hand-edited).
- No AI-assistant attribution in any repo file except the agent-config file; cite "the operating contract".
- Known SBCL durability flake `VOLATILE-LATEJOINER-ZERO`: if it (and only it) fails, re-run `make test-sbcl`; do not chase.

## Strategy / dependency order

Spike-first. T1 (cms-verify) and T2 (XML parser + data model) are independent crypto/parsing units. T3 composes them into the plugin. T4 is the crypto-free disc slot. T5 is the manager (composes T3 + T4 + the Slice-2 auth-remote). T6 proves end-to-end. T7 is the capstone.

```
T0 spike ─┬─ T1 dds-dare cms-verify (FFI) + KAT
          └─ T2 XML lib + parser + data model + allow/deny matcher + fuzz
T1,T2 ──── T3 plugin (validate-local/remote-permissions + check_* predicates)
T3 ─┬─ T4 disc permissions-gate slot + compose (crypto-free)
    └─ T5 access-control manager (dds-dcps) + check_create_* wiring ── T6 integration (headline) ── T7 capstone
```

- Produces: `cms-verify (smime-octets ca-store) -> (or (simple-array (unsigned-byte 8) (*)) null)` — verify the S/MIME/CMS `smime-octets` against `ca-store` (the Permissions CA `X509_STORE*`), returning the VERIFIED CONTENT bytes (the inner XML) or `nil` on ANY failure (fail-closed).

- [ ] **Step 1: Failing CMS KAT.** Load the T0 `governance.xml.p7s` (or `.smime`) + the Permissions CA; assert `cms-verify` returns the inner XML bytes (non-nil, contains `domain_access_rules`); a 1-byte-tampered copy → `nil`; verification against the WRONG CA → `nil`.

```lisp
(defun* run-cms-verify-kat () (function () t)
  (let* ((ca   (dds.dare:x509-load-ca *perm-ca-pem*))
         (good (dds.dare:cms-verify *governance-smime* ca)))
    (unwind-protect
         (progn (assert good)
                (assert (search (map '(vector (unsigned-byte 8)) #'char-code "domain_access_rules") good))
                (assert (null (dds.dare:cms-verify *governance-smime-tampered* ca))))
      (dds.dare:x509-ca-free ca)))
  t)
```
