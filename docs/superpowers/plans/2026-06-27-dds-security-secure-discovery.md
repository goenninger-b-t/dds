# DDS-Security Secure Discovery — Implementation Plan (M7 / P6, Slice 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement OMG DDS-Security 1.1 secure discovery end-to-end (submessage protection + whole-RTPS-message protection + origin authentication + a reliable ParticipantVolatileMessageSecure endpoint + the Governance protection-kind model + the secure builtin discovery endpoints), proven our-to-our and against a live Fast DDS-Security peer.

**Architecture:** Additive crypto-plugin tiers under `src/dds-security/crypto/` reusing the Slice-1 AES-256-GCM codec via a shared `CryptoHeader/Content/Footer` element; a dedicated `crypto-manager` (dds-dcps) owning the §8.5 ParticipantCrypto + EntityCrypto key registries and the crypto-token exchange; the reliable PVMS endpoint reusing the existing RTPS reliable engine; the secure builtin endpoints wired into the existing SPDP/SEDP/WLP discovery code; the gate ladder's `:keyed` precondition deepened to "crypto established". Security-OFF stays byte-identical.

**Tech Stack:** Common Lisp (SBCL + Clasp), `dds-dare`/OpenSSL (AES-256-GCM, HMAC-SHA256), `static-vectors` via `dds.pal`, the existing `dds.cdr` buffer/cursor + `dds-rtps` message codec + `dds-disc` discovery engine.

**Spec:** `docs/superpowers/specs/2026-06-27-dds-security-secure-discovery-design.md` (read it; this plan implements it).

## Global Constraints

- OMG DDS-Security 1.1 / DDSI-RTPS 2.5 / XCDR conformance is non-negotiable; the only allowed deviation is interop behavior added *on top*, never replacing. **A false REJECT is the worst defect class.**
- **Never write a wire constant from memory.** Every EntityId, submessage-kind, PID, KDF label, `message_class_id`, and struct layout is pinned in **T0** into `src/dds-security/crypto/constants.lisp` (or the existing constants file), each with its `§clause` cite + a dual-corroboration note (Fast DDS source + tshark/spec for Connext). Later tasks import those names — never re-type a literal.
- **No hand-rolled crypto.** AES-256-GCM / HMAC-SHA256 only through `dds-dare` (`aes-256-gcm-seal`/`-open`, `hmac-sha256`).
- **Bounds-check every network-facing parse before every read, even at `(safety 0)`.** Fail-closed: malformed/truncated/out-of-order/missing/MAC-mismatch/GCM-fail → drop, never signal out of the receive thread, never deliver unverified plaintext, never fall back to plaintext. Resource caps reject before allocation. Each new decoder gets a `(safety 0)` fuzz arm.
- **Hot path** (`encode/decode_rtps_message`, `encode/decode_*_submessage` — they run per datagram): `defstruct`+monomorphic functions, crypto scratch buffers from the static arena via `dds.pal:alloc-static`, zero alloc/sample in steady state, and a **before/after bench** in `bench/report/`. Control-plane code (governance, key mgmt, token exchange) is not hot-path.
- `defun*` / `defstruct*` (from `dds.lang`) + a full `ftype`/typed lambda list on every function (FR-LANG-8). No reader conditionals (`#+sbcl` etc.) outside `dds-pal/`.
- **Clasp AND SBCL both validate, Clasp first.** Each task runs `make test-clasp` then `make test-sbcl` (or the targeted equivalent) before commit.
- Docs in lockstep: docstrings on every exported symbol + `docs/wiki/security.md` + `README.md` + `docs/verification.csv` (capstone T13). SBOM auto-regenerated by the pre-commit hook (never hand-edit). No AI/"Claude" attribution in any repo file — cite "the operating contract §N".
- Secrets/keys live in `dds.pal` foreign buffers (`alloc-static`/`free-static`), freed on teardown.
- Commit per task with a message referencing `WP-DDS-SECURITY-SECURE-DISCOVERY` + the requirement/clause ids. **Within-branch commits are autonomous; HOLD PUSH until the owner says "push".**

## Spec refinement recorded here (DRY vs "additive")

The spec §4.1 said "leave Slice-1 `crypto.lisp`/`transform.lisp` untouched." Honoring the operating contract's **no-duplication** rule overrides that: **T1 extracts** the shared `CryptoHeader/Content/Footer` codec into `crypto/crypto-header.lisp` and **refactors `crypto.lisp` to call it**, so the serialized-payload tier and the new submessage/RTPS tiers share one codec. The Slice-1 byte-exact corpus is the regression guard proving the refactor is byte-identical. (Flagged to the owner at plan handoff.)
