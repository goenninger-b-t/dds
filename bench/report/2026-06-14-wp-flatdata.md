# WP-FLATDATA — ser/deser cost + ZC-RX vs classic (honest) (FR-PF-4, NFR-PERF-7, FR-LANG-7)

**NOT cleared for ship — pending counsel (R6); see ADR 0015.** FlatData + Zero-Copy are R6 patent-gated.

Phase E1a of WP-FLATDATA: quantify the cost of a FINAL fixed-size FlatData type (`fd-abc`: `u8`/`u32`/`u64`, 20-octet payload) against the CLASSIC per-field codec for the SAME type, over the EXACT functions the engine funcalls. Per the operating contract no hot-path change lands without a before/after measurement; this is that measurement. Generated by `dds.tests:run-bench-flatdata` (entry: `make bench-flatdata`).

## Method

Each path is measured over the FUNCTION the engine actually funcalls (the type-support vtable slot), not a hand-rolled stand-in. GC bytes/op is the `dds.pal:bytes-consed` delta over the loop (NFR-PERF-8 oracle; SBCL-exact, Clasp reports 0 — a documented NFR-PORT gap). ns/op is total elapsed (`dds.pal:monotonic-ns`, ~microsecond resolution) divided by the iteration count: a single op reads 0 on this clock, so the per-op figure is the amortised loop time (the same method `perftest.lisp` uses) and is a coarse RELATIVE indicator, not an absolute single-op latency. The TX serialize loop resets the write cursor + re-writes the encap header each iteration (as `%serialize-sample` does); the RX loops re-parse the encap header each iteration (as `%deserialize-sample` does). Reusable write/RX buffers are PAL-static and freed at the end.

## Serialize / deserialize / accessor cost — FlatData vs classic (same `fd-abc`)

| path | FD bytes/op | FD ns/op | classic bytes/op | classic ns/op | note |
|------|-------------|----------|------------------|---------------|------|
| **TX serialize** (engine `:serialize`) | 0.0 | 35.1 | 31.8 | 43.6 | FlatData = block-copy identity, 0 per-field encode (the TX win) |
| **RX deserialize** (engine non-ZC `:deserialize`) | 79.9 | 147.6 | 128.1 | 113.1 | FlatData allocs 1 buffer/sample; win = modest GC-heap + 0 per-field decode |
| **RX deser into loaned target** (0-alloc inner) | 0.0 | 11.6 | 128.1 | 113.1 | the path Phase-D ZC uses (loaned target = the slot); 0-alloc |
| **Offset accessor GET** (`a`:u8 + `b`:u32, fixnum) | 0.0 | 6.4 | 0.0 | 0.0 | read in place, 0-alloc (no classic equivalent — struct slots) |
| **Offset accessor SET** (`a`:u8 + `b`:u32, fixnum) | 0.0 | 6.6 | 0.0 | 0.0 | write in place, 0-alloc |
| **Offset accessor GET** (`c`:u64 > fixnum) | 31.8 | 5.9 | 0.0 | 0.0 | read in place IS 0-copy, but returning a >fixnum u64 BOXES a bignum (a Lisp cost, not FlatData) |

## FlatData over Zero-Copy — RX (safe single copy out of SHMEM, NOT literal-0-copy)

| RX path | GC bytes/sample | vs v1 |
|---------|-----------------|-------|
| WP-FLATDATA-over-ZC single-copy (`%zc-resolve-fresh`) | 79 | 1x |
| WP-ZEROCOPY-v1 sink(65536)+re-copy | 65551 | 830x |

The FlatData-over-ZC RX allocates ONE exact-length (20-octet) owned vector, read in place from the SHMEM slot under a single mutex hold — no 65536-byte scratch sink, no second copy: a **830x** reduction in RX GC bytes/sample vs WP-ZEROCOPY-v1.

## Honest framing (FR-LANG-7) — no path is claimed ~0 unless it measures ~0

- **TX serialize** and **RX-into-loaned-target** are the only GENUINELY ~0-alloc paths (block-copy identity / copy into a caller-owned buffer; the loaned buffer IS the ZC slot on the Phase-D path).
- The **engine-visible non-ZC RX vtable** (`deserialize-<name>-fd`) allocates ONE FlatData buffer per sample (79.9 bytes/op here) — modestly below the classic per-field decode (128.1) with 0 per-field work, NOT zero. The classic vtable likewise allocates a fresh sample per call.
- The **FlatData-over-ZC RX is a SAFE SINGLE COPY out of shared memory** (~830x less than WP-ZEROCOPY-v1's sink+re-copy — ~3 orders of magnitude), **NOT literal-0-copy**. A Lisp octet-buffer cannot wrap a raw foreign SAP, and ZC delivery is into an async store read on another thread with no slot-aware release hook, so a literal-0-copy SHMEM VIEW would be a cross-process use-after-free. **TX still has the one app->slot copy** (a loan-write API is the follow-up). **Literal-0-copy RX is DEFERRED** — it needs SAP-backed accessors plus a DCPS-level refcount-spanning ZC read path (ADR 0015, Phase-D outcome).

Method: 200000 iterations (100000 for ZC-RX); GC bytes/op = `dds.pal:bytes-consed` delta (SBCL-exact, Clasp=0); ns/op = `dds.pal:monotonic-ns` total/iters (~us clock, amortised). Impl: SBCL 2.6.5-85913ede1 on goede012.local.
