# WP-FLATDATA-LOAN-WRITE — zero-copy TX (write the sample straight into the SHMEM pool slot) (FR-PF-4, FR-LANG-7)

**NOT cleared for ship — pending counsel (R6); see ADR 0042.** `dds.disc:*zerocopy-enabled*` is default OFF and the per-type `:flatdata t` opt-in is off by default; this report exercises the loan-write path with both armed inside the bench only.

The app-facing loan-write TX API (`loan-sample`/`write-loaned`/`discard-loan`) writes a FlatData sample **directly into the writer's shared-memory pool slot** through the SAP-mode `<name>-<field>-fd` Offset setters, eliminating BOTH intra-host TX copies the shipped Zero-Copy TX path pays: (1) the app→payload identity copy (`serialize-<name>-fd`) and (2) the payload→slot copy (`%zc-loan`). Measured over the EXACT pool primitives the loan path funcalls (`%zc-loan-acquire` / the SAP Offset setters / `%zc-loan-commit`). Generated by `dds.tests:run-bench-flatdata-loan-write` (entry: `make bench-flatdata-loan-write`).

## Method

Each row runs one full writer TX cycle `iters` times over a shared pool. BASELINE = `serialize-fd-abc-fd` (app→payload identity copy) + `%zc-loan` (payload→slot block copy) + `%zc-release`. LOAN-WRITE = `%zc-loan-acquire` + the three SAP Offset setters (`a`,`b`,`c` written straight into the slot) + `%zc-loan-commit` + `%zc-release`. GC bytes/sample = `dds.pal:bytes-consed` delta / iters (SBCL-exact, Clasp=0); ns/sample = `dds.pal:monotonic-ns` total / iters (~us clock, amortised). Both cycles loan + release one slot, so the delta is exactly the two eliminated copies vs the direct field writes.

## TX per-sample cost — baseline (two copies) vs loan-write (zero copies)

| TX path | GC bytes/sample | ns/sample | copies |
|---------|-----------------|-----------|--------|
| BASELINE `%serialize-sample` (fresh payload) + `%zc-loan` | 159.9 | 254.8 | 2 (app→payload, payload→slot) |
| **LOAN-WRITE** acquire + SAP setters + commit | **32.1** | **167.4** | **0** (fields written straight into the slot) |

Loan-write writes the sample **straight into shared memory** — **0** intra-host TX copies. Its **32.1** GC bytes/sample is ONLY the fixed pool-mutex acquire (a payload-independent CFFI residue the baseline `%zc-loan` ALSO pays); it eliminates the per-sample heap SerializedPayload the shipped write path allocates (the baseline's **159.9** includes that 20-octet fresh vector), so the loan-write steady state allocates **no per-sample payload** — the slot is foreign, the view + loan bookkeeping recycle through freelists. In ns, the shipped two-copy path costs **254.8** ns/sample; loan-write costs **167.4** ns/sample — a ~1.5x TX-primitive speedup, the app→payload intermediate buffer and its identity block-copy eliminated entirely.

## Send-site arm — the ADR 0042 integration (pre-committed slot vs fresh `%zc-loan`, 8 KiB sample)

The end-to-end delta: for a loan-written change the send plan's `%zc-change-item` CLAIMS the pre-committed slot and builds the 20-octet-ref DATA item with **no payload→slot copy**; a `write-sample` change takes `%zc-ref-builder` → `%zc-loan`, copying the 8192-octet payload into a fresh slot. Both arms build the identical DATA bytes into a scratch cursor and release the slot (as the resolving reader would). 50000 iterations each.

| send-site path | GC bytes/sample | ns/sample | payload→slot copy |
|----------------|-----------------|-----------|-------------------|
| `write-sample` path: `%zc-ref-builder` → `%zc-loan` (copy) | 224.1 | 20097.7 | 8192 octets |
| **loan-write path: acquire+commit + claim (`%zc-armed-item`)** | **222.8** | **602.1** | **0** |

The loan-write send site emits the ref **33.4x faster** for this 8 KiB sample (the eliminated copy scales with payload size); GC bytes/sample are the identical fixed item-build cost (the 20-octet ref vec + the builder closure) on both arms.

## DCPS-cycle arm — the honest app-visible write cost (FR-LANG-7)

The REAL `loan-sample` -> `-fd` setters -> `write-loaned` cycle vs `write-sample` on a reused FlatData buffer, unmatched writer, 20000 iterations. **v1 `write-loaned` is NOT 0-GC**: it allocates the RETAINED payload vector (it lives in the writer HistoryCache to serve retransmission / non-ZC / extra-ZC destinations — reuse would corrupt history) plus two registry list cells; the loan struct + view recycle through the freelist. This is the documented v1 cost, the same order as `write-sample`'s `%serialize-sample` payload; it is eliminated only by the acked-slot-pinning follow-up (ADR 0042 Follow-ups). NOTE the configuration: with NO ZC destination and a tiny 20-octet sample, loan-write's benefit (the eliminated send-site copy) cannot appear, so its fixed overhead (slot acquire/commit + the slot->heap retained copy + the sweep) makes the cycle SLOWER than `write-sample` here — the win requires a same-host ZC reader and scales with payload size (the send-site arm above: ~29x at 8 KiB). The 0-copy and 0-GC claims are scoped precisely: the SEND-SITE payload->slot copy is eliminated (send-site arm) and the POOL PRIMITIVES are 0-GC (primitive table); v1 `write-loaned` itself is NOT 0-GC.

| DCPS write cycle | GC bytes/sample | ns/sample |
|------------------|-----------------|-----------|
| `write-sample` (reused FlatData buffer) | 507.4 | 858.2 |
| `loan-sample` -> setters -> `write-loaned` | 844.8 | 1459.8 |

|-------------|------------------|
| literal-0-copy loan RX (`%zc-acquire-for-read` + SAP read) | 0.0 |

The RX-side loan path is untouched by this WP (the `%zc-loan` split is behaviour-identical); the literal-0-copy loan RX still allocates 0.0 GC bytes/sample vs the v1 single-copy's 79.0 — no regression vs `bench/report/2026-06-16-wp-flatdata-zc-loan.md`.

Correctness envelope (ADR 0042 §5, as shipped): loan-write is an OPTIMIZATION of the ZC TX path — every existing case (non-ZC readers, reliable retransmit, late-joiners, pool saturation, multi-destination) is served identically from the RETAINED payload `write-loaned` materialises once. The PRE-COMMITTED slot is consumed at the FIRST ZC-eligible destination (exactly-one-ZC-destination = the pure end-to-end envelope, proven by `dcps-loan-write-e2e`); any further ZC destination pays a fresh `%zc-loan` exactly as today, a retransmit always uses the retained payload, and a slot the send pass never consumes is released by the fallback decision / the push-pass sweep / the teardown sweep (never a strand, ADR 0042 lifecycle).
