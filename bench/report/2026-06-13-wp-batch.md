# WP-BATCH — write-side batching throughput

Date: 2026-06-13
Requirement: FR-PF-1, NFR-PERF-4, FR-LANG-7
Harness: `dds-bench` `run-throughput :batch N`, SBCL, UDP loopback, RELIABLE, single in-process pair.
Method: writer blasts 20 000 × 64 B samples with `batch-max-samples = N` (publish defers the push until N
accumulate, then flushes coalesced); reader counts delivery; report writer-side send rate.

## Result (20 000 × 64 B, reliable)

| batch N | received | send samples/s | vs unbatched |
| ------- | -------- | -------------- | ------------ |
| 1 (off) | 20 000   | 7 985          | 1×           |
| 10      | 20 000   | 514 933        | 64×          |
| 50      | 20 000   | 647 396        | 81×          |
| 100     | 20 000   | 761 412        | **95×**      |

All 20 000 samples are delivered at every batch size (reliability preserved). `send samples/s` is the
writer-side publish rate (the per-sample syscall + handshake overhead that batching amortizes): at N=100,
20 000 writes become ~200 datagrams (≤100 DATA + 1 HEARTBEAT each) instead of 20 000, so the per-sample
fixed cost drops ~95×. This is the NFR-PERF-4 lever for small-sample throughput.

## How it works (wire-standard, default-off)
`publish-sample` accumulates the write in the HistoryCache and defers `%push-data` until
`batch-max-samples` accumulate (size trigger) or `flush-batch` fires (the announce cadence / `stop-node`,
the time trigger). Each sample stays a normal DATA submessage (RTPS 2.5 §9.4.5.4); the existing coalescer
(`%send-packed`) packs the batch into few datagrams with one trailing HEARTBEAT, so the reliable
HEARTBEAT/ACKNACK handshake is amortized over the batch. The READER is unchanged. `batch-max-samples=1`
(default) flushes every write — every existing test/path is unaffected.

## Trade-off
Batching trades LATENCY for THROUGHPUT: a batched sample waits up to the batch fill / cadence flush.
Default-off; enable per writer via `make-disc-node :batch-max-samples N`.

## Out of scope
RTI-proprietary batch wire format (multiple samples in ONE DATA payload) — needs a Connext capture to
byte-validate (deferred). A fine-grained configurable batch-DELAY timer (cadence flush bounds staleness
now). `sendmmsg`/`recvmmsg` syscall batching (FR-XPORT-6).
