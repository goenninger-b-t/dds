# Fast DDS LogEvent leg (cross-DDS interop, FR-IO-2 / ADR 0082 §3)

A **Fast DDS 3.6.1** `@appendable dds::log::LogEvent` publisher — the second independent vendor (with
the Connext leg, `../../log/`) proving the `LogEvent` wire type interoperates. `log_pub.cpp` publishes
on topic `DdsLog`, generated by `fastddsgen` from the ONE canonical `../../log/DdsLog.idl` (no copy).

## Result

**INTEROPERATES (Fast DDS writer → our reader).** 192 samples, every field decoded across the vendor
boundary, including an IPv6 `host_ip`, the two enums, and the five bounded strings. This leg found the
IDL's third cross-vendor defect: **fastddsgen rejects explicit enum values** (`SEV_EMERG = 0`), so
`Severity` now uses plain sequential values (identical wire; both vendors generate) — see
`../../log/README.md`.

## Run

```sh
# copy the shared UDPv4-loopback profile + guard (git-ignored duplicates, like the appendable leg)
cp ../appendable/profiles.xml ../appendable/participant_guard.hpp .
../../../scripts/with-fastdds.sh bash -c 'make gen && make log_pub'   # fastddsgen + clang
../../../scripts/with-fastdds.sh bash -c './log_pub 0 400'            # publish LogEvent on DdsLog
# our reader (unicast SPDP to the loopback-pinned Fast DDS peer):
../../../scripts/with-sbcl.sh --load ../../log/log_sub.lisp
```

`fastddsgen` output (`gen/`), the `log_pub` binary, and the copied `profiles.xml` /
`participant_guard.hpp` are git-ignored (clean-room: generated / copied locally, never checked in).
